# Known gaps

Findings recorded while documenting the commit in [docs/README.md](README.md#version-documented).
Nothing was fixed as part of the documentation task. Each item says how it was established.

## Confirmed implementation issues and limitations

| #   | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Evidence                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------- |
| 1   | **The Storage deletion queue drains only opportunistically**, from `after()` callbacks when a reviewer opens `/admin/membership`, after a membership decision, and after a permanent deletion. It returns early unless the **membership** Storage configuration is complete, even for queued event covers, project images and member photos. With no reviewer activity, or without the membership bucket variables, queued objects stay in Storage. There is no scheduled job. | **Source** (`lib/membership/server.ts` `processMembershipStorageDeletions`) |
| 2   | **Host separation is off in production.** `CORE_API_HOST_ENFORCEMENT` is not enabled: `https://api.essqu.com/admin/login` serves the dashboard, so the API and admin trees are reachable on each other's hostnames.                                                                                                                                                                                                                                                            | **Deployed** (2026-10-24)                                                   |
| 3   | **`GET` member routes write.** `GET /v1/me/membership` links and may activate, `GET /v1/me/profile` may sync the email, and `GET /v1/me/events` and `GET /v1/me/events/{id}/attendance` link guest registrations. Intentional and audited, but they are not safe or idempotent in HTTP terms, and caches or prefetchers must not call them.                                                                                                                                    | **Source**                                                                  |
| 4   | **`/v1/health` checks the database only**: schema version and reachability. Supabase Auth and Storage outages are invisible to it.                                                                                                                                                                                                                                                                                                                                             | **Source**                                                                  |
| 5   | **A legacy routine stays callable.** `private.register_for_event` (the original guest routine) remains executable by `app_runtime` but is no longer called. The application uses `register_event_guest`.                                                                                                                                                                                                                                                                       | **Source** (catalog and caller search)                                      |
| 6   | **`members.status = 'graduate'` is unreachable.** No routine sets it. If set by hand, member routes accept the graduate but project writes refuse them, while the website still offers project submission.                                                                                                                                                                                                                                                                     | **Source**                                                                  |
| 7   | **CSV exports work only from the `APP_ORIGIN` host.** Production exports require the browser `Origin` to equal `APP_ORIGIN`. The dashboard answers on several hosts (`engsoc-platform.vercel.app`, `admin.essqu.com`, `api.essqu.com`), and `.env.example` suggests `https://engsoc-platform.vercel.app`, so exports fail from the other hosts unless the setting matches the host in use.                                                                                     | **Source**; impact **Inferred**                                             |
| 8   | **Default CORS origins are narrow.** Unset `CORE_API_ALLOWED_ORIGINS` allows only `https://essqu.com` and `https://www.essqu.com`. `essqu-web.vercel.app`, Preview origins and localhost must be configured explicitly. The variable is missing from `.env.example`.                                                                                                                                                                                                           | **Source**                                                                  |
| 9   | **Account erasure needs `SUPABASE_SERVICE_ROLE_KEY`** to finish. Without it, erasures stay "pending" after the database part. This is by design and is retried from the overview.                                                                                                                                                                                                                                                                                              | **Source**                                                                  |
| 10  | **Own registrations are capped** at the 100 most recent events (`list_own_registrations`). Older registrations are not listed.                                                                                                                                                                                                                                                                                                                                                 | **Source**                                                                  |

## Missing features and incomplete flows

- `public.certificates`, `public.archive_items` and `public.mentorship_connections` exist from the
  original model, but no code issues certificates, manages the archive or handles mentorship. The
  website's certificate and network pages are Coming Soon prototypes.
- No transition into or out of `graduate`.
- No membership suspension (ADR 0024: no approved policy).
- No automatic expiry or deletion of applications, members or records: intentionally excluded by
  the owner.
- The public event DTO has no type, end time, capacity counts, disciplines, programme or Arabic
  text. The website keeps those designs hidden.
- No scheduled jobs and no webhooks: there is no on-demand revalidation signal to the website, and
  the Storage queue drains opportunistically.
- Administrators' Auth sessions cannot be invalidated by Core when access is revoked. Authorization
  still ends on the next request (ADR 0014).

## Recommendations

These are suggestions, not decisions:

1. Resolve the production Supabase project question with the owner first. It affects data
   protection and every rollout note.
2. Drain the Storage deletion queue independently of the membership bucket and of reviewer
   activity, for example with an authenticated maintenance trigger.
3. Enable `CORE_API_HOST_ENFORCEMENT` once both hostnames are confirmed, and set `APP_ORIGIN` to
   the dashboard's canonical host.
4. Add the project endpoints and current servers to `openapi.v1.yaml`. Update the stale README,
   `CLAUDE.md` status, `db/README.md` and ADR 0024 header.
5. Add `CORE_API_ALLOWED_ORIGINS` and `CORE_API_HOST_ENFORCEMENT` to `.env.example`. Mark
   `RESEND_API_KEY` as unused or remove it.
6. Bring `db/schema.ts` in line with the migrations, or document it as intentionally partial at
   the top of the file.
7. Revoke `EXECUTE` on the unused `register_for_event` in a future migration, if nothing external
   depends on it.
8. Consider extending `/v1/health` (or a separate check) to report Auth and Storage reachability
   without disclosing configuration.
